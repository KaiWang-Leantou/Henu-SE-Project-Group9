│ 浏览器                                                       │

## 2. 一次请求的链路

### 2.1 登录

```
① 浏览器 POST /api/auth/register  {username, password}
② Nginx 命中 location /api/ → proxy_pass 127.0.0.1:8080
③ Spring Boot：AuthController → AuthService
      ├─ BCrypt 校验/加密密码
      └─ JwtService 签发 token（HS256，12h）
④ 返回 {code:"OK", data:{token, user}}
⑤ 前端存 localStorage，之后每个请求带 Authorization: Bearer <token>
```

### 2.2 画一笔

```
① 前端 pointerdown/move：本地先画（乐观渲染）
② 每 40–60ms 发一次 stroke.append（不落库、不定序）
③ 抬笔发 stroke.end
④ 服务端：进入房间串行执行器 → 应用命令 → seq++ → 广播 op → 回 ack
⑤ 前端收到 op：按 id 幂等去重；收到 ack：移出未确认队列
⑥ 快照线程：2 秒防抖后写 doc_json，并广播 saved
```

## 3. 前端

### 3.1 Vue 3 —— 组件化与响应式

**作用**：把界面拆成可复用的组件树，数据变化自动更新 DOM。

**核心概念**：

| 概念 | 含义 | 我们的用法 |
| :--- | :--- | :--- |
| 单文件组件 `.vue` | 模板 + 逻辑 + 样式写在一个文件 | `BoardView.vue`、`DrawView.vue` |
| `ref()` / `reactive()` | 响应式数据 | `settings` 用 `reactive`，滑块一改光标样式立刻变 |
| `computed` | 派生状态 | 作品库的筛选结果 |
| `watch` | 监听变化做副作用 | `watch(settings, persist)` 自动落 localStorage |
| `props` / `emit` | 父子通信 | `BoardCanvas` 向外抛事件 |
| `v-if` / `v-for` | 条件与列表渲染 | 版本时间轴、成员列表 |

**最小示例（我们的写法风格）**：

```vue
<script setup lang="ts">
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">{{ count }}</button>
</template>
```

**为什么不用 jQuery**：白板状态复杂（成员、光标、版本、分页），命令式操作 DOM 很快失控；Vue 的声明式渲染让"状态 → 界面"单向可推导。

### 3.2 TypeScript —— 多人协作的安全网

**作用**：给 JavaScript 加静态类型，**编译期**发现错误，而不是等用户点出来。

```ts
// 协议类型（frontend/src/net/protocol.ts）
interface Member {
  id: string
  name: string
  role: 'owner' | 'editor' | 'viewer'
  color: string
}

function drawCursor(m: Member) { /* ... */ }

drawCursor({ id: 'u1', name: '张三' })   // ❌ 编译报错：缺少 role 和 color
```

**关键点**：

- 类型只在编译期存在，运行时被擦除，**不影响性能**
- 联合类型（`'owner' | 'editor'`）能穷举协议里的枚举值
- `npm run build` 里先跑 `vue-tsc --noEmit`，类型不过就不打包

### 3.3 Vite —— 开发快、生产打包

**作用**：开发服务器 + 生产构建工具。**不是渲染加速**。

| 阶段 | 做了什么 | 结果 |
| :--- | :--- | :--- |
| `npm run dev` | 不打包！浏览器按原生 ES Module 按需请求，Vite 只即时编译当前文件 | 启动 < 1s，改代码热更新（HMR） |
| `npm run build` | 依赖合并、压缩、tree-shaking、按路由拆包 | 产出 `dist/` |

**产物结构（实测）**：

```
dist/
├── index.html               0.7 KB
└── assets/
    ├── index-xxxx.js      107 KB（gzip 41 KB）
    ├── BoardView-xxxx.js   56 KB（按路由拆包）
    └── index-xxxx.css      39 KB
```

> ⚠️ **常见误解**：`npm run build` 产出的是**静态文件**，不是 jar。jar 由 Maven 产出。

**版本注意**：`vite ^8`（Vite 8 底层换成了 Rolldown）。Vite 7 依赖 esbuild 子进程，在受限环境会 EPERM，**不要降级**。

### 3.4 Vue Router —— 页面分流

| 路由 | 页面 | 说明 |
| :--- | :--- | :--- |
| `/login` | 登录/注册 | 可游客进入 |
| `/home` | 主界面 | 三个入口 |
| `/draw` | 作品库 | 全部/已归档/回收站 + 版本抽屉 |
| `/collab` | 联机 | 选板建房 |
| `/board/:id` | 画布 | 协同编辑 |
| `/guess` | 你画我猜 | 占位（V2） |

**守卫**：`/home`、`/draw`、`/collab` 需要登录；`/board/:id` 不拦截，内部自动建游客身份。

### 3.5 画布内核 —— 纯 TypeScript，与框架解耦

**为什么自己写而不上 Fabric.js / Konva**：

- 白板只需要"笔划 + 后续图形"，不需要完整对象模型
- 外部库的对象模型会和"服务端全序同步"打架（谁改了什么难以对齐）
- 纯 TS 内核不依赖 Vue，测试和替换 UI 都更容易

**渲染策略**：

| 层 | 内容 | 何时重绘 |
| :--- | :--- | :--- |
| 底图 canvas | 已落定的笔划 | 文档变化时 |
| 覆盖 canvas | 当前笔划、他人笔划、光标 | 每帧（`requestAnimationFrame` 合帧） |

**关键细节**：

- 所有点存**世界坐标**，缩放平移只作用于渲染层
- `devicePixelRatio` 适配高分屏
- 指针事件用 `getCoalescedEvents()` 拿到更密的采样点

### 3.6 前后端通信

| 环境 | 前端请求 | 去向 |
| :--- | :--- | :--- |
| 开发 | `http://localhost:5173/api/...` | Vite 代理 → `127.0.0.1:8080` |
| 线上 | `http://IP/api/...` | Nginx 反代 → `127.0.0.1:8080` |

**关键约定**：代码里永远写**相对路径 `/api`**，换环境不用改代码。

**WS 客户端要做的事**（`net/client.ts`）：

- `join{lastSeq}` 加入/重连
- 未确认命令队列 + `ack` 清理
- `seq` 不连续时重新 `join` 补发
- 指数退避重连（1→2→4→…→15s）
- `ping` 25s 心跳
- 光标 50ms 节流

## 4. 后端

### 4.1 Spring Boot —— 应用容器

**作用**：把 Web 服务器、JSON 序列化、依赖注入、配置管理打包好，一个 `main()` 就能起服务。

**为什么是 fat jar**：`mvn package` 产出可执行 jar，**内嵌 Tomcat**，服务器上只要有 JDK 17 就能 `java -jar` 跑，**不需要单独装 Tomcat**。

**Profile（多环境配置）**：

| profile | 数据库 | 用途 |
| :--- | :--- | :--- |
| `dev`（默认） | H2 文件库 `backend/data/` | 本地开发，零安装 |
| `mysql` | MySQL 8 | 服务器部署 |

切换方式：`java -jar app.jar --spring.profiles.active=mysql`

### 4.2 WebSocket —— 服务器主动推送

**为什么不用 HTTP 轮询**：画布要求 50ms 级同步，轮询要么延迟大要么请求爆炸。

**为什么不用 SSE**：SSE 只能服务端 → 客户端单向，画布需要双向。

**握手过程**：

```
浏览器 GET /ws  with headers:
    Upgrade: websocket
    Connection: Upgrade
    Sec-WebSocket-Key: xxx
服务器 101 Switching Protocols
之后双方随时互发文本帧（JSON）
```

**Nginx 必须配合**（否则连不上）：

```nginx
proxy_set_header Upgrade    $http_upgrade;
proxy_set_header Connection $connection_upgrade;
proxy_read_timeout 3600s;   # 默认 60s 会掐断长连接
```

### 4.3 房间与全序 —— 一致性的核心

**问题**：两个人同时画，谁先谁后？

**我们的方案**：**服务端全序广播**。

```
每个 board 一个 Room
  └─ SerialExecutor（单线程队列）
       收到 op → 应用 → seq++ → 广播给房间所有人
```

**为什么这样就够了**：

- 所有客户端按**同一个 seq 顺序**应用**同一组操作**
- 合并函数是确定性的 → 最终状态必然相同（收敛）
- 因此**不需要 OT，也不需要 CRDT**（那两套是为"无中心/离线"准备的）
- 代价：必须联网、必须有一个中心服务端——正好符合我们的场景

**重连补发**：

```
客户端 join{lastSeq: 800}
服务端：从环形缓冲（最近 500 条）补发 801..N
       缺口过大 → 改为下发全量 init
```

### 4.4 Spring Data JPA —— 对象映射

**作用**：用 Java 对象操作数据库，不手写 SQL。

```java
@Entity
@Table(name = "wb_board")
public class BoardEntity {
    @Id private String id;
    private String name;
    private String ownerId;
    @Column(columnDefinition = "MEDIUMTEXT") private String docJson;
    private Long docSeq;
    // getter / setter
}

public interface BoardRepository extends JpaRepository<BoardEntity, String> {
    List<BoardEntity> findByOwnerId(String ownerId);
}
```

调用：`boardRepository.findById(id)` → 返回 `Optional<BoardEntity>`。

### 4.5 Flyway —— 表结构的版本管理

**作用**：把建表/改表写成有编号的 SQL，**启动时自动执行**，并记录执行历史。

```
src/main/resources/db/migration/
├── V1__baseline.sql         建 wb_board、wb_board_op
├── V2__user_and_member.sql  建 wb_user、wb_board_member
└── V3__board_version.sql    建 wb_board_version
```

- 命名规则：`V<版本号>__<描述>.sql`（两个下划线）
- 执行记录表：`flyway_schema_history`
- **已执行的脚本不能改**，要改就新增 `V4__xxx.sql`

**为什么 `ddl-auto: none`**：JPA 默认会按实体自动建表，和 Flyway 冲突。我们规定 **Flyway 是唯一真源**，JPA 只负责增删改查。

### 4.6 JWT —— 无状态鉴权

**结构**：`header.payload.signature`，三段 Base64URL 用点连接。

```json
// payload 解码后
{ "sub": "u_7f3a21", "guest": false, "name": "张三", "iat": 1763..., "exp": 1763... }
```

**校验流程**：

```
请求头 Authorization: Bearer <token>
  → AuthFilter 取 token
  → 用 WB_JWT_SECRET 验签
  → 解析出 userId 放进 UserContext（ThreadLocal）
  → 请求结束清理
```

**为什么 WS 用 query 传**：浏览器 `new WebSocket()` **不支持自定义请求头**，只能 `ws://host/ws?token=xxx`。

**代价**：签发后无法单独作废，只能等过期或换密钥（全量失效）。所以有效期设 12 小时。

### 4.7 BoardPlugin —— 游戏接缝

**作用**：白板内核不知道"你画我猜"的存在，游戏通过接口挂上去。

```java
public interface BoardPlugin {
    String channel();                                   // "game"
    void onJoin(Room room, Member member);
    void onMessage(Room room, Member member, JsonNode msg, Consumer<JsonNode> reply);
    boolean canWrite(Room room, Member member, String cmdType, JsonNode cmd);  // 写权限钩子
    void onCommitted(Room room, Member member, long seq, String channel, JsonNode cmd);
}
```

游戏接管后：`canWrite` 只放行"当前画手 + 当前轮次页"，词只私发画手。

## 5. 数据与存储

### 5.1 MySQL 8.0

**为什么**：SRS 指定；事务、并发、备份工具成熟；课程答辩认可度高。

**关键参数**：

- `utf8mb4`：支持中文和 emoji（`utf8` 只有 3 字节，存不下 emoji）
- `InnoDB`：支持事务
- 连接串必须带：`useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true`

### 5.2 H2（开发环境）

嵌入式文件数据库，`jdbc:h2:file:./data/wb`，零安装、单进程访问，适合本地开发和自动化测试（测试用 `MODE=MySQL` 保证语法兼容）。

### 5.3 存储模型：快照 + 操作日志

```
每次操作 → 追加 wb_board_op（轻量）
        ↓ 2 秒防抖 / 累计 50 条
     写 wb_board.doc_json（整板快照）
```

**为什么不全量写**：每笔都写整板 JSON 会造成写放大，几百笔就卡。
**为什么保留 op 日志**：崩溃恢复、审计、版本回放。

## 6. 网关与进程管理

### 6.1 Nginx

**四个职责**：

| 职责 | 配置 |
| :--- | :--- |
| 托管静态文件 | `root /var/www/whiteboard; try_files $uri $uri/ /index.html;` |
| 反代 REST | `location /api/ { proxy_pass http://127.0.0.1:8080; }` |
| 反代 WebSocket | `location /ws { proxy_set_header Upgrade ...; proxy_read_timeout 3600s; }` |
| SPA 路由回退 | `try_files ... /index.html`（否则刷新 `/draw` 会 404） |

### 6.2 systemd

**作用**：把 Java 进程变成"系统服务"——开机自启、挂了自动重启、日志进 journald。

```ini
[Service]
User=wb
ExecStart=/usr/bin/java -jar /opt/whiteboard/app.jar --spring.profiles.active=mysql
Restart=always
[Install]
WantedBy=multi-user.target
```

| 命令 | 作用 |
| :--- | :--- |
| `systemctl start/stop/restart whiteboard` | 立即启停 |
| `systemctl enable/disable whiteboard` | 开机自启开关 |
| `journalctl -u whiteboard -f` | 实时日志 |

## 7. 协作机制专题

### 7.1 为什么不上 OT / CRDT

| 方案 | 适合 | 我们的情况 |
| :--- | :--- | :--- |
| OT | 文本编辑，中心服务器 | 变换函数复杂，画布场景收益低 |
| CRDT | 离线编辑、P2P | 内存开销大，理解成本高 |
| **全序广播** | 有中心、需强一致 | ✅ 实现简单、可解释、够用 |

笔划是**追加型**（不可变），天然没有冲突；只有"图形被两人同时拖动"才需要裁决，而 `seq` 顺序天然给出裁决。

### 7.2 版本回滚五步

```
① 当前文档存为 PRE_RESTORE 版本
② 目标版本 doc 覆盖当前 doc，seq = max(当前, 目标) + 1
③ 落一条 op：board.restore{versionId, versionNo}
④ 更新 wb_board.doc_json / doc_seq / last_saved_at
⑤ 广播 init，所有客户端全量重同步
```

**历史只追加**：回滚不删版本，所以"回滚的回滚"永远可行。

### 7.3 归档与只读

状态机：`DRAFT → ACTIVE → ARCHIVED → TRASHED`。

- 归档 = 只读，不是删除
- 回收站 30 天后物理清除（规划）
- 服务端在 `MessageRouter` 入口拦截写命令，返回 `READ_ONLY`

## 8. 选型对照表

| 决策点 | 我们选的 | 替代方案 | 理由 |
| :--- | :--- | :--- | :--- |
| 前端框架 | Vue 3 | React | 中文资料多、模板语法直观 |
| 构建工具 | Vite 8 | Webpack | 冷启动快、配置少 |
| 画布 | 自研纯 TS | Fabric / Konva | 与全序同步模型契合，体积小 |

| 鉴权 | JWT | Session | 无状态，WS 友好 |
| 数据库 | MySQL 8 | PostgreSQL | SRS 指定，教学环境通用 |
| 网关 | Nginx | Caddy | 资料多，答辩好讲 |

## 10. 常见误解清单

| 误解 | 事实 |
| :--- | :--- |
| "Vite 是渲染加速" | 它是构建工具/开发服务器；渲染性能靠 Canvas 与 rAF |
| "npm run build 出 jar" | 出的是 `dist/` 静态文件；jar 由 Maven 产出 |
| "JPA 会自动建表，所以不用管数据库" | 我们设了 `ddl-auto: none`，表结构只由 Flyway 管 |
| "WebSocket 就是长轮询" | 它是独立的协议，握手后是全双工帧 |
| "JWT 能随时踢人下线" | 无状态 token 签发后无法单独作废，只能等过期或换密钥 |
| "上线就是把 jar 丢上去" | 还要 Nginx 反代、systemd 托管、环境变量、数据库 |
| "端口开着方便调试" | 8080/3306 只能监听 127.0.0.1，公网只开 80/443 |
