# 01 · 数据模型

> 版本：`schemaVersion = 1`　|　最后更新：2026-11-13

## 1. 原则

1. **笔划只追加、不可变**。`stroke` 落定后只读，橡皮 = 删除操作，绝不"白色覆盖"。
2. **服务端全序**。所有操作由服务端串行分配 `seq`，客户端严格按 `seq` 应用 → 所有客户端必然收敛，**不需要 Lamport 时钟 / CRDT**。
3. **坐标存世界坐标**。缩放、平移只在渲染层变换，任何持久化与网络传输都不含屏幕坐标。
4. **一页一画布**。游戏每轮开一页，白板天然支持多页。

## 2. 概念模型

```
Board（白板）
 └─ Page（页，可多页；游戏里一页 = 一轮）
     └─ Element[]（按绘制顺序排列）
         ├─ Stroke（笔划，不可变）
         ├─ Shape（矩形/圆/箭头/直线，可改）
         └─ Text（文本，可改）
```

## 3. 文档 JSON

整块 board 内容以一个 JSON 存在 `wb_board.doc_json`，同时通过 WS `init` 全量下发。

```json
{
  "schemaVersion": 1,
  "boardId": "b_7f3a",
  "seq": 812,
  "pages": [
    {
      "id": "p_1",
      "name": "第 1 页",
      "roundId": null,
      "elements": [
        {
          "kind": "stroke",
          "id": "s_9f21",
          "author": "u_2a",
          "createdAt": 1763000000123,
          "tool": "pen",
          "color": "#111111",
          "width": 4,
          "points": [120.5, 300.0, 124.0, 306.5, 131.0, 315.0]
        }
      ]
    }
  ]
}
```

| 字段 | 类型 | 必有 | 说明 |
| :--- | :--- | :--- | :--- |
| `schemaVersion` | int | ✓ | 结构版本，当前 `1` |
| `boardId` | string(32) | ✓ | 与 DB 主键一致 |
| `seq` | long | ✓ | 文档已应用到的最新服务端序号 |
| `pages` | Page[] | ✓ | 有序，至少 1 页 |

**Page**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | string(32) | `p_` + 随机 |
| `name` | string(50) | 显示名；游戏页写"第 N 轮" |
| `roundId` | string\|null | 游戏轮次 ID；普通白板页为 `null` |
| `elements` | Element[] | **按绘制顺序**；绘制顺序即图层顺序 |

**Element 公共字段**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `kind` | enum | `stroke` / `rect` / `ellipse` / `arrow` / `line` / `text` |
| `id` | string(32) | 全局唯一，`s_` 笔划、`o_` 图形/文本 |
| `author` | string(32) | 创建者 userId |
| `createdAt` | long | 创建时间（epoch ms） |

**Stroke 专有**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `tool` | `"pen"` | 目前只有笔；橡皮走删除，不产生 stroke |
| `color` | string | `#RRGGBB` |
| `width` | number | 世界坐标下的线宽（1–64） |
| `points` | number[] | **扁平数组** `[x1,y1,x2,y2,...]`，世界坐标；单笔上限 4000 点 |

> 扁平数组比对象数组省 40% 以上体积，且序列化更快。

**Shape 专有**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `x` `y` `w` `h` | number | 世界坐标包围盒（允许负 w/h 表示反向拖拽） |
| `rotation` | number | 弧度，默认 0 |
| `fill` | string\|null | `null` 表示不填充 |
| `stroke` | string | 描边色 |
| `strokeWidth` | number | 描边宽 |

**Text 专有**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `x` `y` | number | 左上角世界坐标 |
| `text` | string | 内容，≤ 500 字符 |
| `fontSize` | number | 16–96 |
| `color` | string | `#RRGGBB` |

## 4. 一致性模型（为什么不需要 OT/CRDT）

| 场景 | 处理 |
| :--- | :--- |
| 两人同时画 | 两笔独立追加，服务端各分配 `seq`，顺序无影响 |
| 同一笔划被两端同时结束 | 服务端以先到的 `stroke.end` 为准，后到者被忽略（幂等） |
| 图形被两端同时拖动 | 后到的 `object.patch` 覆盖先到的（全序即 LWW，但由 `seq` 决定，无需时钟） |
| 先删后改 | 删除后对已删元素的 `patch` 直接丢弃 |
| 断线重连 | `join.lastSeq` 补发缺失 op；缺口过大发全量 `init` |

> 结论：**全序广播本身就保证收敛**。Lamport 时钟只有在支持"离线编辑"时才需要，本项目 V1 不做离线。

**乐观本地应用**：客户端先本地渲染再等 `ack`。若同一元素被远端 `seq` 更晚的操作覆盖，以 `op` 消息为准（客户端直接重放，不做回滚动画，避免跳变）。

## 5. MySQL 8.0 表结构

```sql
CREATE TABLE wb_board (
  id          VARCHAR(32)  NOT NULL PRIMARY KEY,
  name        VARCHAR(100) NOT NULL,
  owner_id    VARCHAR(32)  NOT NULL,
  doc_json    JSON         NULL COMMENT '最新快照；NULL 表示从未落盘',
  doc_seq     BIGINT       NOT NULL DEFAULT 0 COMMENT '快照对应的 seq',
  is_public   TINYINT(1)   NOT NULL DEFAULT 1,
  created_at  DATETIME(3)  NOT NULL,
  updated_at  DATETIME(3)  NOT NULL,
  KEY idx_owner (owner_id),
  KEY idx_updated (updated_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE wb_board_member (
  board_id  VARCHAR(32) NOT NULL,
  user_id   VARCHAR(32) NOT NULL,
  role      VARCHAR(16) NOT NULL COMMENT 'OWNER / EDITOR / VIEWER',
  joined_at DATETIME(3) NOT NULL,
  PRIMARY KEY (board_id, user_id),
  KEY idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE wb_board_op (
  board_id   VARCHAR(32) NOT NULL,
  seq        BIGINT      NOT NULL,
  actor_id   VARCHAR(32) NOT NULL,
  ch         VARCHAR(16) NOT NULL COMMENT 'board / game',
  cmd_json   JSON        NOT NULL,
  created_at DATETIME(3) NOT NULL,
  PRIMARY KEY (board_id, seq),
  KEY idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE wb_user (
  id         VARCHAR(32) NOT NULL PRIMARY KEY,
  nickname   VARCHAR(50) NOT NULL,
  avatar     VARCHAR(255) NULL,
  is_guest   TINYINT(1)  NOT NULL DEFAULT 1,
  created_at DATETIME(3) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE wb_word (
  id         BIGINT      NOT NULL AUTO_INCREMENT PRIMARY KEY,
  category   VARCHAR(32) NOT NULL COMMENT '动物/食物/动作/电影…',
  content    VARCHAR(50) NOT NULL,
  difficulty TINYINT     NOT NULL DEFAULT 1,
  UNIQUE KEY uk_content (category, content)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE wb_game_session (
  id         VARCHAR(32) NOT NULL PRIMARY KEY,
  board_id   VARCHAR(32) NOT NULL,
  mode       VARCHAR(16) NOT NULL COMMENT 'classic / relay',
  state_json JSON        NOT NULL COMMENT '状态机快照',
  created_at DATETIME(3) NOT NULL,
  ended_at   DATETIME(3) NULL,
  KEY idx_board (board_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6. Redis key 设计

| key | 类型 | TTL | 用途 |
| :--- | :--- | :--- | :--- |
| `wb:room:{boardId}:members` | Hash（userId → Member JSON） | 心跳续期 90s | 在线成员与角色 |
| `wb:room:{boardId}:seq` | String | 无 | 序号冗余（单实例以内存为准，多实例必须用） |
| `wb:room:{boardId}:cursor` | Hash | 10s | 光标位置（易失） |
| `wb:game:{boardId}` | Hash | 2h | 游戏会话状态 |
| `wb:rl:{userId}` | String | 1s | 限流计数 |

> **不要**把画板数据放 Redis（见 SRS 隐患）。画板在内存 + MySQL 快照。

## 7. 持久化流水线

```
客户端 op → 服务端校验 → 分配 seq → 写 wb_board_op（异步批量，200ms flush）
                                   → 广播 op
                 ↓ 防抖（2s 空闲 或 累计 50 op）
            写 wb_board.doc_json + doc_seq（同一事务）
```

- 启动恢复：读 `doc_json`，再补 `seq > doc_seq` 的 `wb_board_op`。
- 写放大控制：**绝不每笔写快照**，只写 op 行 + 定期快照。
- 清理：`wb_board_op` 保留最近 7 天（定时任务），更早已被快照覆盖。
- 崩溃窗口：最多丢 2s 内未 flush 的操作（课设可接受，可调 500ms）。

## 8. 容量估算

| 对象 | 单条大小 | 量级 |
| :--- | :--- | :--- |
| 一条 stroke（100 点） | ≈ 1.1 KB JSON | 500 笔 ≈ 550 KB |
| 一页上限 | 建议 2000 笔 | 单页 JSON < 3 MB |
| 房间 op 日志 | 按天增长 | 单房间 1 万 op/天 ≈ 20 MB |

> 超过单页上限时提示"新开一页"，不要硬撑——Canvas 绘制 5000 笔以上必然掉帧。
