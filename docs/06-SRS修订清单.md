## 2. §2.3 全局业务规则：追加 3 条

- 每个白板有且仅有一个创建者（owner），owner 可转让、可归档、可删除。
- 白板归档后**只读**：可查看、可导出，不可编辑；回收站中的白板 30 天后由系统物理清除。
- 未登录用户以游客身份参与协作，但不能创建作品、存档或回滚；游客可升级为正式账号且数据不丢失。

## 4. §4.1 性能要求：追加可度量指标

| 指标 | 目标 | 测量口径 |
| :--- | :--- | :--- |
| 作品库列表加载 | P95 < 300 ms（≤50 条） | 服务端日志计时 |
| 登录 / 注册响应 | P95 < 500 ms | 压测工具 50 并发 |
| 版本回滚 | < 1 s（单板 ≤2000 笔） | 端到端计时 |
| 自动存稿 | 编辑后 ≤2 s 落库 | 观察 `last_saved_at` |

> 原文档"延迟 100ms""Redis 毫秒级"缺少测量口径，建议统一成这种表格，避免验收时扯皮。

## 5. §4.2 设计约束：追加

- 数据库：MySQL 8.0（开发环境使用 H2 文件库模拟，表结构由 Flyway 版本化迁移管理）。
- 鉴权：JWT（HS256，12 小时有效期），密码使用 BCrypt（cost=10）单向哈希存储。
- 接口风格：RESTful（`/api` 前缀）+ WebSocket（`/ws`），统一返回信封 `{code,message,data}`。

## 6. 新增 §4.7 安全需求

- 密码不得明文存储或写日志；登录失败不区分"用户不存在"与"密码错误"。
- 所有写操作必须服务端校验身份与角色，前端隐藏按钮不作为权限依据。
- 私有白板非成员访问须返回 403；越权尝试记录审计日志。
- 单连接消息频率限制 60 帧/秒；单笔笔划点数上限 4000。
- 用户输入（昵称、白板名）长度受限并在渲染时转义，防 XSS。

## 7. 新增 §4.8 数据保留与备份

| 数据 | 保留策略 |
| :--- | :--- |
| 白板快照 | 永久（每板一份最新） |
| 操作日志 | 最近 7 天，超期清理 |
| 自动版本 | 最近 30 个 + 每天首个，保留 30 天 |
| 手动版本 | 永久（单板 ≤100） |
| 回收站作品 | 30 天后物理清除 |

备份：每日 `mysqldump` 全量 + 演示前手动导出一次（备份脚本放 `deploy/`）。

## 8. §4.6 验收要求：改成可勾选清单

把"完全可用、无严重 Bug"替换为：

- [ ] 两个账号互相看不到对方未公开的作品
- [ ] 非 owner 修改他人白板名称返回 403
- [ ] 刷新页面内容不丢；**重启后端后内容仍在**
- [ ] 回滚到 5 分钟前的版本，画布内容正确恢复
- [ ] 归档后只读；从回收站恢复成功
- [ ] 3 人同时协作 10 分钟无掉线、笔划不重影

## 10. 如果时间不够，怎么砍

优先级从高到低：`F-06 用户` > `F-07 作品库` > `F-08 自动存稿` > `F-09 版本` > `F-10 归档`。
**F-06 和 F-07 不能砍**——它们直接回应教师的两条意见；F-09 至少要保留"自动版本 + 回滚一条路径"，否则"云端存稿"没有说服力。
