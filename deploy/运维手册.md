> 这是**部署者个人**的操作手册，组员开发不需要看。
> 服务器：阿里云 Ubuntu，公网 IP `47.101.33.69`，Nginx 1.24，MySQL 8，JDK 17。

## 1. 服务器上的文件地图

| 路径 | 内容 | 属主 |
| :--- | :--- | :--- |
| `/opt/whiteboard-src/` | git clone 的源码（更新用） | 你的登录用户 |
| `/opt/whiteboard/app.jar` | 后端可执行 jar | `root`（只读即可） |
| `/opt/whiteboard/` | 后端工作目录 | `wb:wb` |
| `/var/www/whiteboard/` | 前端 `dist/` 静态文件 | `www-data:www-data` |
| `/etc/whiteboard/wb.env` | 环境变量（JWT 密钥、数据库密码） | `wb:wb`，权限 `600` |
| `/etc/systemd/system/whiteboard.service` | 后端服务定义 | `root:root` |
| `/etc/nginx/conf.d/whiteboard.conf` | Nginx 站点配置 | `root:root` |
| `/var/log/nginx/` | 网关日志 | `www-data` |
| `journalctl -u whiteboard` | 应用日志（不在文件里，由 journald 管） | 系统 |

**一句话**：源码在 `-src`，运行物在 `whiteboard`，网页在 `/var/www`，配置在 `/etc`，日志在 journald。

## 2. `wb` 用户

### 2.1 它是什么

操作系统里的**系统账户**（`useradd -r`），没有密码、不能 SSH 登录，只用来"以最低权限运行服务"。

### 2.2 定义在哪（三层）

| 层 | 位置 | 作用 |
| :--- | :--- | :--- |
| ① 账户本身 | `/etc/passwd`、`/etc/shadow`、`/etc/group` | 定义 UID/GID/家目录/shell |
| ② 谁以它运行 | `/etc/systemd/system/whiteboard.service` 的 `User=wb`、`Group=wb` | 启动时切换身份 |
| ③ 它能动什么 | 目录属主 + `/etc/whiteboard/wb.env` 的 `600` | 文件系统权限 |

> 注意：**系统用户 `wb`** 和 **MySQL 用户 `wb`** 是两个独立的东西，只是同名。前者管进程身份，后者管数据库连接。

### 2.3 查看

```bash
id wb
getent passwd wb
sudo grep '^wb:' /etc/shadow          # 第二个字段是 ! 表示禁止登录

sudo systemctl show whiteboard -p User -p Group -p WorkingDirectory -p EnvironmentFiles
ps -eo user,pid,cmd | grep '[a]pp.jar' | head -3      # 应显示 wb

sudo ls -ld /opt/whiteboard /etc/whiteboard /etc/whiteboard/wb.env
```

### 2.4 权限矩阵

| 路径 | 期望 | 说明 |
| :--- | :--- | :--- |
| `/opt/whiteboard` | `wb:wb 755` | 应用要写临时文件 |
| `/opt/whiteboard/app.jar` | `root:root 644` | 只读即可 |
| `/etc/whiteboard/wb.env` | `wb:wb 600` | 只有应用能读密钥 |
| `/var/www/whiteboard` | `www-data:www-data 755` | Nginx 读，跟 wb 无关 |

### 2.5 修改

```bash
# 改 shell（服务账户不需要登录能力）
sudo usermod -s /usr/sbin/nologin wb

# 改目录属主
sudo chown -R wb:wb /opt/whiteboard

# 换运行用户（unit 里改完必须 daemon-reload）
sudo nano /etc/systemd/system/whiteboard.service
sudo systemctl daemon-reload && sudo systemctl restart whiteboard
```

## 3. systemd 服务

### 3.1 单位文件逐段解释

```ini
[Unit]
Description=Whiteboard Backend (Spring Boot)
After=network-online.target mysql.service   # 等网络和 MySQL
Wants=network-online.target

[Service]
Type=simple
User=wb                                     # 以 wb 身份运行
Group=wb
WorkingDirectory=/opt/whiteboard            # 相对路径的基准
EnvironmentFile=/etc/whiteboard/wb.env      # 注入环境变量
Environment=TZ=Asia/Shanghai
ExecStart=/usr/bin/java -Xms256m -Xmx512m -XX:+UseSerialGC \
          -jar /opt/whiteboard/app.jar --spring.profiles.active=mysql
Restart=always                              # 挂了自动重启
RestartSec=5
SuccessExitStatus=143                       # 被 SIGTERM 停掉不算失败
StandardOutput=journal
StandardError=journal
SyslogIdentifier=whiteboard
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=multi-user.target                  # enable 时挂到开机流程
```

> ⚠️ **不要再加 `ReadWritePaths=/opt/whiteboard/data`**：目录不存在时 systemd 直接 `status=226/NAMESPACE` 起不来。生产用 MySQL 不需要它。

### 3.2 常用命令

```bash
sudo systemctl status whiteboard --no-pager -l     # 状态 + 最近日志
sudo systemctl restart whiteboard                  # 重启（换 jar 后）
sudo systemctl stop whiteboard
sudo systemctl start whiteboard
sudo systemctl enable whiteboard                   # 开机自启
sudo systemctl disable whiteboard                  # 取消开机自启
sudo systemctl cat whiteboard                      # 看 unit 内容
sudo systemctl show whiteboard -p Restart -p User  # 看生效值
```

### 3.3 日志

```bash
sudo journalctl -u whiteboard -f                  # 实时
sudo journalctl -u whiteboard -n 100 --no-pager   # 最近 100 行
sudo journalctl -u whiteboard --since today       # 今天
sudo journalctl -u whiteboard -p err              # 只看错误
sudo journalctl --vacuum-size=200M                # 清理旧日志
```

### 3.4 三种修改方式

| 改什么 | 操作 | 是否 reload |
| :--- | :--- | :--- |
| 换 jar | `scp` 覆盖 `/opt/whiteboard/app.jar` → `restart` | 不需要 |
| 改 `wb.env` | 编辑后 `restart` | 不需要 |
| 改 unit（内存/端口/用户） | 编辑 → `daemon-reload` → `restart` | **需要** |
| 改 Nginx | `nginx -t` → `reload nginx` | 与后端无关 |

## 4. 启动与关闭的顺序

**原则**：启动从内到外（数据库 → 应用 → 网关），关闭从外到内（网关 → 应用 → 数据库）。

### 4.1 只重启后端（最常用）

```bash
sudo systemctl restart whiteboard
```

### 4.2 完整停机维护

```bash
sudo systemctl stop nginx         # ① 先断入口
sudo systemctl stop whiteboard    # ② 再停应用（优雅关闭连接）
sudo systemctl stop mysql         # ③ 最后停数据库
```

> 反过来先停 MySQL，应用会疯狂报错并触发 `Restart=always` 反复重启。

### 4.3 完整启动

```bash
sudo systemctl start mysql
sudo systemctl start whiteboard
sudo systemctl start nginx
```

### 4.4 确认停干净

```bash
sudo ss -lntp | grep -E ':80 |:8080 |:3306 '
```

三个端口都不再监听即可。

### 4.5 手动运行（不通过 systemd，排查用）

```bash
cd /opt/whiteboard
sudo -u wb bash -c 'set -a; . /etc/whiteboard/wb.env; set +a; java -jar app.jar --spring.profiles.active=mysql'
```

前台运行，错误直接打印；`Ctrl+C` 停止。

后台运行：

```bash
nohup java -jar app.jar --spring.profiles.active=mysql > /opt/whiteboard/app.log 2>&1 &
echo $! | sudo tee /opt/whiteboard/app.pid
sudo kill $(cat /opt/whiteboard/app.pid)      # 停止（不要 -9）
tail -f /opt/whiteboard/app.log
```

## 5. Nginx

### 5.1 配置放在哪

Ubuntu 的 `/etc/nginx/nginx.conf` 同时 include 两处：

```nginx
include /etc/nginx/conf.d/*.conf;
include /etc/nginx/sites-enabled/*;
```

两种习惯**等价**：

| 方式 | 优点 | 适合 |
| :--- | :--- | :--- |
| `conf.d/whiteboard.conf`（当前） | 一个文件，不用建链 | 单站点 |
| `sites-available/` + 软链 `sites-enabled/` | `a2ensite`/`a2dissite` 一键启停，多站点 | 一台机多网站 |

切换方式：

```bash
sudo mv /etc/nginx/conf.d/whiteboard.conf /etc/nginx/sites-available/whiteboard
sudo ln -s /etc/nginx/sites-available/whiteboard /etc/nginx/sites-enabled/whiteboard
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

> 别两个目录放同一份配置，否则报 `duplicate default server`。

### 5.2 改配置的标准流程

```bash
sudo nano /etc/nginx/conf.d/whiteboard.conf
sudo nginx -t                     # 必须通过再 reload
sudo systemctl reload nginx       # 平滑重载，不断连接
```

| 命令 | 效果 |
| :--- | :--- |
| `reload` | 平滑加载新配置，现有连接不中断 ✅ |
| `restart` | 停掉再启，短暂 502 |

### 5.3 关键配置点

```nginx
location /api/ { proxy_pass http://127.0.0.1:8080; }

location /ws {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 3600s;
}

location / { try_files $uri $uri/ /index.html; }   # SPA 回退
```

## 6. 数据库

### 6.1 建库与账号（只做一次）

```bash
sudo mysql
```

```sql
CREATE DATABASE wb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'wb'@'localhost' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON wb.* TO 'wb'@'localhost';
FLUSH PRIVILEGES;
```

- **库要手动建**；**表由 Flyway 启动时自动建**
- `utf8mb4` 才能存中文和 emoji

### 6.2 日常查看

```bash
sudo mysql -e "SHOW DATABASES;"
sudo mysql wb -e "SHOW TABLES;"
sudo mysql wb -e "SELECT id,nickname,guest,created_at FROM wb_user ORDER BY created_at DESC LIMIT 10;"
sudo mysql wb -e "SELECT id,name,status,last_saved_at FROM wb_board LIMIT 10;"
sudo mysql wb -e "SELECT version,description,success FROM flyway_schema_history;"
sudo mysql -e "SHOW GRANTS FOR 'wb'@'localhost';"
```

### 6.3 备份与恢复

```bash
mkdir -p /opt/backup
mysqldump -u wb -p wb | gzip > /opt/backup/wb-$(date +%F-%H%M).sql.gz

# 恢复
gunzip -c /opt/backup/wb-2026-11-14-1700.sql.gz | mysql -u wb -p wb

# 保留 7 天
find /opt/backup -name 'wb-*.sql.gz' -mtime +7 -delete
```

建议 crontab：

```bash
sudo crontab -e
0 3 * * * /opt/backup/wb-backup.sh
```

### 6.4 改密码 / 排查连接

```bash
sudo mysql -e "ALTER USER 'wb'@'localhost' IDENTIFIED BY '新密码'; FLUSH PRIVILEGES;"
# 同步改 /etc/whiteboard/wb.env 里的 WB_DB_PASSWORD，然后 restart

mysql -h 127.0.0.1 -u wb -p wb -e "SELECT 1;"     # 验证凭据
```

### 6.5 图形化

DBeaver / Navicat 用 **SSH 隧道**连：主机填 `127.0.0.1`，隧道填服务器 IP + SSH 账号。MySQL 只监听本机，外网直连不通是正常的。

## 8. 排障手册

| 现象 | 先查 | 常见原因 | 处理 |
| :--- | :--- | :--- | :--- |
| 页面 502 | `systemctl status whiteboard` | 后端没起 | 看 journalctl |
| 页面 502 | `ss -lntp \| grep 8080` | 端口没监听 | 同上 |
| `status=226/NAMESPACE` | unit 里 `ReadWritePaths` | 目录不存在 | 删掉该行 + daemon-reload |
| `Connection refused`（Nginx 日志） | 后端进程 | 后端崩了 | 看日志 |
| 注册提示"无法连接服务器" | 浏览器 F12 → Network | 上游 502 | 按上面排查 |
| 日志 `Unknown database 'wb'` | `SHOW DATABASES` | 库没建 | 执行建库 SQL |
| 日志 `Access denied for user 'wb'` | `wb.env` 密码 | 密码不一致 | 改 env 或 ALTER USER |
| 日志 `Communications link failure` | `systemctl status mysql` | MySQL 没起 | 启动 MySQL |
| 日志 `Port 8080 was already in use` | `ss -lntp \| grep 8080` | 残留进程 | kill 后 restart |
| 刷新 `/draw` 404 | Nginx `try_files` | 没配 SPA 回退 | 补 `try_files ... /index.html` |
| WS 连不上 | `location /ws` | 缺 Upgrade 头/超时 | 补配置后 reload |
| 登录后很快掉线 | 系统时间 | 时钟漂移导致 JWT 过期 | `timedatectl set-ntp true` |
| 内存越用越少 | `free -h` | JVM + MySQL 抢内存 | `-Xmx512m`、`innodb_buffer_pool_size=128M`、加 swap |
| 磁盘满 | `df -h` | 日志堆积 | `journalctl --vacuum-size=200M`、清 `/var/log` |

## 9. 安全清单

- [ ] 安全组只放行 `22`、`80`（以后 `443`）
- [ ] `8080` 只监听 `127.0.0.1`（`SERVER_ADDRESS=127.0.0.1`）
- [ ] MySQL 只监听 `127.0.0.1`，不对外
- [ ] `wb.env` 权限 `600`，属主 `wb`
- [ ] 服务以 `wb` 运行，不用 root
- [ ] `WB_JWT_SECRET` 是随机生成的，未进 git
- [ ] SSH 用密钥登录，禁用密码（`PasswordAuthentication no`）
- [ ] 定期备份数据库
- [ ] 域名备案后再上 HTTPS（Let's Encrypt / certbot）
